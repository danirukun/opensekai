## Current state

- **Calibration.** The MediaPipe retargeter (`apps/desktop/src/tracking/retarget.ts`) keeps the first face matrix as the neutral head. `calibrate()` clears it, so the next frame becomes the neutral. The worker accepts `{kind:'calibrate'}` and the tracker has `calibrate()`, but no editor control, command, or MCP tool calls it. The neutral lives only in the worker: it changes each time the tracker starts, and it is not saved. The upper body (chest) has no neutral. VMC and iFacialMocap have no calibration. The iFacialMocap head rotation is a raw bone; the sender's zero is the neutral.
- **Face mapping.** The session (`packages/session/src/tracking.ts`) passes expressions through unchanged, multiplied by the stale fade weight. MediaPipe clamps to 0..1. There is no sensitivity, no per-blend-shape range, no linked blink, and no head or eye intensity. Expression suppression (blink, mouth, brow) exists in `expressions.ts` (B4).
- **Offsets.** The B5 bone offset layer is a per-tick Blueprint layer. It is not a source setting and it is not saved. There is no head rotation offset on a source.
- **Source mixing.** `AvatarTracking` is `{ bodySourceId, faceSourceId }`. Face bones (`head`, `neck`, `leftEye`, `rightEye`, `jaw`) and expressions come from the face source; all other bones come from the body source. A finger source next to a VMC body is not possible. B5 rejects a patch that makes two avatars use one source.
- **Smoothing.** Each source has an optional `smoothing` field and a `setTrackingSmoothing` patch operation, in TypeScript and in Rust (`crates/contracts`). The composer keeps a raw and a filtered sample for each source. This is the pattern for new source settings.
- **Names.** iFacialMocap sends `eyeBlink_L`; MediaPipe sends `eyeBlinkLeft`. `canonicalArkitName` in `packages/contracts/src/expressions.ts` maps both to `eyeBlinkLeft`.

## Decisions

These decisions are reversible. The owner can change each one in review of this contract before code exists. Decisions 1, 3, and 5 add optional fields to the show format; old shows load without change.

1. **Calibration is saved on the source.** A tracking source gets an optional `calibration` field: the neutral rotation of each calibrated bone. A new patch operation `calibrateTracking { entityId }` captures it from the current smoothed sample in the session, and `setTrackingCalibration { entityId, calibration }` sets or clears it. The capture is a normal persistent edit: it changes the scene revision, and a saved show keeps it. The editor has no scene undo (OSE-09); a second Calibrate replaces the value and Reset clears it. Alternative: a runtime calibration that is lost on restart, as the MediaPipe worker does now.
2. **One calibration rule for all kinds.** For each calibrated bone, the session applies `inverse(neutral) × rotation`, before mapping and mixing. The calibrated bones are the ones in the sample from this set: `hips`, `spine`, `chest`, `upperChest`, `neck`, `head`. Thus the captured pose becomes the sender's zero. Eyes, arms, and fingers are not calibrated. VMC can be calibrated too, but Warudo says that the VMC sender calibrates, so the editor shows Calibrate only for iFacialMocap and MediaPipe. MCP can calibrate each kind. Alternative: a calibration for face sources only.
3. **The MediaPipe neutral moves to the session.** The worker no longer keeps a first-frame neutral; it sends the face rotation in camera space. Without a saved calibration, the neutral is the camera axis (identity). Thus the session is the one authority and the neutral does not change when the tracker restarts. Alternative: keep the first-frame neutral when no calibration is saved. That gives a different neutral at each start.
4. **Calibration stays when the config changes.** `setTrackingConfig` (for example a new camera or port) does not clear the calibration, because the performer is the same. One exception: a MediaPipe `mirror` change clears it, because the mirror changes the sign of the captured rotations. The user clears it in other cases with Reset. Alternative: clear it on each config change.
5. **Face mapping is one source setting.** A tracking source gets an optional `mapping` field: head rotation intensity and offset, eye rotation intensity, blend shape sensitivity, linked blink, and a range for each blend shape (input min and max, output min and max). An output max of 0 disables a blend shape, as in Warudo. Patch operation: `setTrackingMapping`. Alternative: Blueprint nodes for each mapping step.
6. **Linked blink uses the larger value.** With Linked Eye Blinking on, both blink channels get `max(left, right)`, so a blink is never lost. Alternative: the mean.
7. **Finger source.** `AvatarTracking` gets an optional `fingersSourceId`. The finger bones of the avatar (30 bones, thumb to little, both sides) come from that source and replace the finger bones of the body source. This is the Warudo **Track Fingers Only** case (for example MediaPipe fingers next to a VMC body). The B5 rule (one source for one performer) covers the new slot. A body source and a finger source can be the same source on one avatar. An iFacialMocap source cannot be a finger source. Alternative: **Tracked Body Parts** for each source, which is a larger model.
8. **No live values in the mapping editor.** Warudo shows live input and output values for each blend shape. The editor does not receive samples today, and adding them changes the editor data path. This slice shows the settings only. Alternative: add a sample view to the editor status stream.
9. **Out of this slice.** Head translation and Body Movement Intensity (they need a hips position path in the renderer), Body Rotation Type (the B5 Upper Body Rotation template covers it), blend shape threshold, eye squint limit, Clamp All BlendShapes, Use Bones/BlendShapes for Eye Movement, MediaPipe hand calibration and the hand settings, Mirrored Tracking for iFacialMocap and VMC, Tracked Body Parts, and Quick Calibration on the character. The owner can move any of them into this slice in review.
10. **No new MCP tools.** MCP reaches each new operation through `scene_patch`. The `scene_patch` description names them.

## Effects

- An operator can look straight ahead and press Calibrate on an iFacialMocap or MediaPipe source. The head and upper body then use that pose as neutral, also after the app restarts.
- An operator can tune the face for each source: head and eye intensity, a head offset, overall blend shape sensitivity, a range for each blend shape, and linked blink.
- An operator can drive fingers from a MediaPipe source and the body from a VMC source on one character.
- The show format gets three optional fields (`calibration` and `mapping` on a tracking source, `fingersSourceId` on avatar tracking) and three patch operations, in TypeScript and Rust. The sample shape and `AvatarPose` do not change. The MediaPipe worker loses its neutral state.

## Risks

- The neutral is one smoothed sample. With smoothing off, a noisy frame becomes the neutral. The user calibrates again.
- A raw iFacialMocap head with a non-identity rest rotation: the calibration maps the captured pose to the sender's zero, as the uncalibrated head does now. The renderer path does not change.
- Removing the MediaPipe first-frame neutral changes the look of a MediaPipe head when the camera is not in front of the user. The user calibrates. A physical camera on macOS shows the result; the cloud cannot.
- A head intensity above 1 extrapolates the rotation angle. With the limit of 2, a head turn above 90 degrees gives a scaled angle above 180 degrees, which shows as the shorter turn the other way. Real head turns are below 90 degrees.
- The MediaPipe head is relative to the chest. Calibrating the chest and the head one by one gives a wrong face when the chest moves, so the contract calibrates that head in the frame above the chest (R4).
- A finger source and a body source from two systems can disagree on the hand frame. The fingers are local rotations in the normalized hand frame, so they do not depend on the arm.
