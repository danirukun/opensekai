## Current state
- The app has no help entry point. [V]
- Rust uses `tauri-plugin-opener` 2.7.2 (`opener().open_url`). The `main` window has no `opener:` permission, and the pinned test `main_capability_has_the_exact_permission_list` (`lib.rs:769`, line 813) asserts this. [V]
- Window commands use `require_window_label` (`lib.rs:52`). `open_camera_settings` (`lib.rs:211`) is the model for a fixed native open. [V]
- `templates.rs` is the model for a fixed table: an unknown ID gives `AppError{code: InvalidInput}`. [V]
- Lucide 1.70.0 has `CircleQuestionMark`. It has no `CircleHelp`. [V]
- Warudo has a help button. Its handbook site does not describe that button. Asset pages are at `/docs/assets/<type>`. [V, handbook read 2026-11-13]

## Risks
- A URL that the webview controls is an open-redirect risk. Mitigation: the webview sends only a topic enum. Rust builds the URL from a fixed table. [V design]
- The pages can claim behavior that is not real. Mitigation: write only the verified behavior, and link to the parity checklist for status.
- Help needs a network connection. Offline, the browser shows its own error. This is acceptable for the first slice. [I]
