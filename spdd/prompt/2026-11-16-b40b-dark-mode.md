# B40b contract: dark mode

Date 2026-11-16 · Scope: theme preference and dark tokens · Issue #183 (UX-05 part) · Analysis: `spdd/analysis/2026-11-16-b40b-dark-mode.md`

## R: Requirements
- R1. Settings has an "Appearance" group above Integrations. It has a kit `Select` labelled "Theme" with System, Light and Dark.
- R2. The default is System. System follows `prefers-color-scheme` and changes when the OS changes.
- R3. A change applies at once, with no reload and no remount. The session continues.
- R4. The preference survives a restart (localStorage `opensekai.theme`).
- R5. The theme applies before the first paint. The window has no flash of the wrong theme.
- R6. The native window frame follows the theme (`setTheme('light'|'dark'|null)`).
- R7. Every editor surface, including the start screen, uses tokens. In dark, text meets WCAG AA 4.5:1 and focus meets 3:1.
- R8. The light theme does not change, except for the `.status-positive` token name and three near-duplicate literals that use the nearest token: the invalid keystroke border `#b3475a` uses error, the expression toggle text `#423c4b` uses text, and the color swatch border `#dedbe5` uses border.

## E: Entities
- `ThemePreference = 'system' | 'light' | 'dark'`; `ResolvedTheme = 'light' | 'dark'`.
- New tokens: `--ds-color-panel` (#f8f8fb), `--ds-color-input` (#fff), `--ds-color-viewport`, `--ds-color-preview`, `--ds-color-preview-check`, `--ds-color-camera-frame`, `--ds-color-shadow`, `--ds-color-shadow-strong`, `--ds-color-warning-bg`, `--ds-color-warning-border`, `--ds-color-warning-text`, `--ds-color-wire`, `--ds-color-wire-hover`, `--ds-color-star`, `--ds-color-debug-warning`, `--ds-color-debug-error`, `--ds-color-link`, `--ds-color-strong-border`, `--ds-color-on-lime`, `--ds-color-hidden-text`.

## A: Approach
- Pure functions decide the theme. A small rune module holds the state.
- `app.css` gets an `html[data-theme='dark']` block after the kit import. It redefines every app token, including the kit tokens that the app uses.
- Ship candidate A (navy tint). The headless check also captures candidate B with an injected style. The owner picks.

## S: Structure
- New: `apps/desktop/src/editor/theme.ts` (pure), `apps/desktop/src/editor/theme.svelte.ts` (state), `apps/desktop/test/theme.test.ts`, `apps/desktop/test/dark-tokens.test.ts`, `docs/evaluation/dark-mode/editor-check.mjs`.
- Changed: `index.html`, `main.ts`, `app.css`, `SettingsPanel.svelte`, the component files with literals (Hierarchy, ContextMenu, AvatarModelField, SceneModelFields, ScreenVideoFields, ScreenImageFields, AvatarExpressionFields, ColorField, LoadOverlay), `capabilities/main.json`, `lib.rs` pinned test, `brand-tokens.test.ts`, `ARCHITECTURE.md`, `docs/warudo-parity.md`.

## O: Operations
- `parseTheme(raw: string | null): ThemePreference` returns `system` for unknown input.
- `resolveTheme(pref, systemDark: boolean): ResolvedTheme`.
- `applyTheme(resolved)` sets `document.documentElement.dataset.theme` and `style.colorScheme`.
- `nativeTheme(pref): 'light' | 'dark' | null` maps `system` to `null`.
- Storage reads and writes use try/catch, as in `blueprints/palette-prefs.ts`.

## N: Norms
- No new copy other than "Appearance", "Theme" and the 3 option names.
- No theme toggle in a toolbar or menu.
- Data colors stay fixed: `editor/lights.ts`, `tracking/mediapipe.ts`, the guide lines and CoachFace.

## S: Safeguards
- `dark-tokens.test.ts` parses the dark block and checks contrast with `theme/contrast.ts`. It also checks that each token in the `:root` block has a dark value.
- `brand-tokens.test.ts` keeps all light pins. The one change is `.status-positive` color `var(--ds-color-on-lime)`. The test comment gives the reason.
- The pinned capability test adds only `core:window:allow-set-theme`.
- A test fails when a `.svelte` file has a hex literal outside an allow list (CoachFace, GuideOverlay).
