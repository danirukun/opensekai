# REASONS: Image screens

Date: 2026-11-04. Scope: MED-01 slice 1. A Screen entity that shows one PNG, JPEG, WebP, or GIF image from the asset library, with its transparency, in the editor, the preview, screenshots, and the OBS output. Analysis: [image screens](../analysis/2026-11-04-image-screens.md). Issue: [GitHub #59](https://github.com/danirukun/opensekai/issues/59).

## R — Requirements

### Asset record

R1. `AssetRecord.format` adds `png`, `jpeg`, `webp`, and `gif` in TypeScript (zod) and Rust. The record adds the optional group `image: { width, height, frames }` (integers; `width` and `height` 1 to 8192, `width × height` at most 33,554,432; `frames` 1 to 4096). TypeScript (`AssetRecordSchema`) and Rust (`AssetRecord` `Validate`) apply the same cross-field rules:
- An image format needs `image`, an ID with the `image_` prefix, `expressions` empty, and no `rig`, `eyeBones`, or `meshes`.
- A `glb` or `vrm` record has no `image` and no `image_` ID.
- Old records validate without change.

`fixtures/protocol/image-records.json` holds valid and invalid records, and a test on each side reads it (as `mesh-names.json` does).
R2. The ID of an image record is `image_` plus the SHA-256 of the stored bytes. The library file extension comes from the format: `png` → `.png`, `jpeg` → `.jpg`, `webp` → `.webp`, `gif` → `.gif`. The registry library load uses the same table. `AssetSummary.kind` adds `image` (TypeScript and Rust), from the `image_` prefix. An image record has `licenseLabel: "User supplied"`, `sourceUrl: null`, `importerVersion: 1`, and no `credits`.

### Import

R3. A new editor-only Tauri command `import_image` opens a native dialog. The dialog title is `Import image`. The filter is `Image` with `png`, `jpg`, `jpeg`, `webp`, and `gif` (no filter label on macOS, as for the other imports). The frontend never sends a path. The command returns the record, as `import_scene` does, and the host sends the `asset-record` event. The command is in each place that `import_scene` is:
- `build.rs` (`commands`)
- `permissions/autogenerated/import_image.toml`
- `capabilities/main.json`
- `generate_handler!` in `lib.rs`
- the exact permission list test in `lib.rs`
- the ports trait in `bootstrap.rs`
- `DesktopState::import_image` in `service/mod.rs`, with the same `AssetStep` hooks

R4. `assets/image.rs` has one pure function `parse_image(bytes) -> Result<ImageHeader, AppError>` (format, width, height, frames). It does not decode pixels. It uses no new crate, and it does not use the `png` crate. It finds the type from the signature only, not from the file extension. Each rule reads only inside the buffer and checks each length before use. Each failure is `INVALID_INPUT` with a message that names the type and the reason. The rules for each type are:
- **PNG:** the 8-byte signature, then a first chunk `IHDR` with length 13. Width and height are the big-endian u32 values. Minimum: 33 bytes.
- **JPEG:** `FF D8 FF`. Walk the markers from offset 2:
  - Skip fill `FF` bytes.
  - Markers `D0`–`D7`, `D8`, and `01` have no length.
  - Each other segment has a big-endian length of at least 2 that stays inside the buffer.
  - The first marker `C0`–`CF` except `C4`, `C8`, and `CC` gives height and width (u16 each, at offsets 3 and 5 of the segment).
  - An `APP1` segment that starts `Exif\0\0` gives the TIFF Orientation tag (0x0112), when present and valid (1 to 8). Orientation 5 to 8 swaps width and height.
  - `DA` (start of scan) or the end of the buffer before a SOF marker is a failure.
  - The walk reads at most the first 1 MiB.
- **WebP:** `RIFF`, a little-endian size that equals the file length minus 8, and `WEBP`. Then the first chunk:
  - `VP8 `: start code `9D 01 2A` at chunk offset 3. Width and height are 14-bit values at offsets 6 and 8.
  - `VP8L`: signature byte `2F`. Width and height are 14-bit values plus 1.
  - `VP8X`: the canvas width and height are 24-bit values plus 1, at offsets 4 and 7.
  - `frames` is 1. An animated WebP shows its first frame.
- **GIF:** `GIF87a` or `GIF89a`. The size is the logical screen width and height (u16 LE). Skip the global color table. Walk the blocks:
  - An image descriptor (`2C`) counts one frame. Skip its local color table, the LZW byte, and its sub-blocks.
  - An extension (`21`) skips its label and sub-blocks.
  - The trailer (`3B`) ends the walk.
  - Each sub-block length must stay inside the buffer. More than 4096 frames, an unknown block, or a buffer end before the trailer is a failure. At least one frame is necessary.
  - A frame larger than the logical screen does not change the size.

The width and height in the record are the display size: the size after the EXIF orientation for a JPEG, and the header size for the other types. A size of 0, a side above 8192, or an area above 33,554,432 is a failure.

R5. The import first checks the file metadata length. Then it reads at most 64 MiB + 1 bytes. A file above 64 MiB fails with `INVALID_INPUT`. The record name is the file stem, cut by `bounded_name` (128 UTF-16 code units on a char boundary), or `Image` when the stem is empty. The same bytes return the existing record, through the deduplication in `AssetRegistry::commit`. `stage_image` stages without the registry lock, and `commit` takes it, as for the scene import.

### Serve and trust

R6. `read_located` (used by the asset service and by `AssetRegistry::read`) branches on `record.format`:
- `glb` and `vrm` run `validate_glb`, as before.
- An image format runs `parse_image`. The detected format must equal `record.format`, and the detected width and height must equal `record.image`.

`Shared::read_asset` returns the bytes and the content type. `GET /assets/{id}` answers `model/gltf-binary`, `image/png`, `image/jpeg`, `image/webp`, or `image/gif`, with `x-content-type-options: nosniff`. The size and SHA-256 checks do not change.

R7. `ARCHITECTURE.md` changes in the same commit. The trust rule now says: a stored asset is one self-contained GLB container, or one PNG, JPEG, WebP, or GIF file whose signature and header the host checks at import and at serve, and the renderer checks at load (R12). The host and the renderer never follow a path or a URL from an image file. Asset path steps 1, 2, and 4 name the image import, the serve check, and the image load.

### Scene

R8. A new entity kind `screen` in TypeScript (zod) and Rust (`SceneEntity::Screen`, `ScreenContent`, with `id()` and `transform()` arms): `{ id, name, visible, transform, kind: 'screen', content: { kind: 'image', assetId: Id | null } }`. `content` is a discriminated union with one member in this slice. A scene has at most 16 screens. The limit is `LIMITS.screens` in the `SceneViewSchema` refine and `MAX_SCREENS` in the Rust `SceneView::validate`. A show without a screen validates without change.
R9. The operation `setScreenImage { entityId, assetId: Id | null }` sets `content` to `{ kind: 'image', assetId }`. It fails with `NOT_FOUND` for an unknown entity and with `INVALID_INPUT` for an entity that is not a screen. It is in `PatchOpSchema`, `LivePatchOp`, and the Rust `PatchOp`. The session does not check that the asset exists or that it is an image, as for `setMeshModel`. The renderer handles a wrong record (R13).
R10. The Blueprint property registry adds `screen` to Position, Rotation, Scale, and Visible, with a registry test row for each. Get Asset Property, Set Asset Property, and Move Entity accept a screen, with transitions. `REFERENCE_KINDS` in `blueprint-file.ts` adds `screen`. A test exports a graph that targets a screen and imports it again.

### Renderer

R11. Each renderer client (OBS page, scene pane preview, editor viewport, and screenshot) draws one quad for each visible screen with a non-null `assetId` that loads. The quad is 1 m high and `record.image.width / record.image.height` m wide, centered on the entity origin, in the local XY plane. It faces local +Z with `DoubleSide`. The front shows the image upright and not mirrored. The back shows it mirrored. The entity transform applies. A screen with `assetId: null` draws nothing. The screen is drawn when the output camera has `renderEnvironment: false`.
R12. Image loading:
- The renderer reads the bytes with `readAsset` and checks the signature again. The signature must be one of the four types and must match the record format.
- It makes the texture with one `createImageBitmap(blob, options)` call. The options are `premultiplyAlpha: 'none'`, `colorSpaceConversion: 'default'`, and `imageOrientation: 'from-image'`. When the longest display side is above the `maxTextureSize` of the quality profile, the same call also gets `resizeWidth`, `resizeHeight` (from the record display size), and `resizeQuality: 'high'`. No second resize step runs.
- The texture has `colorSpace` sRGB and `flipY` set so the front is upright on WebGL 2 and WebGPU.
- A GIF and an animated WebP show the first frame only.
- One texture serves all screens with the same asset in one client. The screen asset IDs are in the `used` set and in `retainOnly`. When no screen uses the asset, the renderer closes the bitmap and disposes the texture.
R13. Screen loads use the load jobs with a new `LoadRequest.kind` `screen`. Each failure of a screen job has the message `Image failed to load`. The failures are: an unknown asset, a GLB or VRM record, a bad or mismatched signature, and a decode failure. The frame warning is `Asset load failed: Image failed to load`, and the Inspector failure message is `Image failed to load`. A failed job retries under the existing rule (a newer revision and 3 s). A failure draws nothing for that screen and does not stop the other entities. A loading image gives the existing `Asset loading` warning. The asset ID branch in `renderer.ts` handles a screen explicitly. A screen is never read as a mesh.
R14. The screen material is unlit (`MeshBasicNodeMaterial`, `toneMapped: false`). Lights, the room map, haze scattering, and shadows do not change it. It does not cast or receive shadows. It is not in a light group, and a light-set rebuild does not touch it.
R15. Transparency:
- At load, the renderer draws the decoded bitmap once into an `OffscreenCanvas` 2D context and reads it with `getImageData`. The bitmap is at most `maxTextureSize` square. When an alpha value is below 255, the image "has alpha". When the read fails, the image has alpha.
- An image with alpha draws with `transparent: true`, normal blending, and `depthWrite: false`. three.js sorts transparent objects by distance. The renderer sets no `renderOrder`. Each other image draws opaque.
- The texture keeps straight alpha, and the material blends once.
- Over the cleared transparent background, an output pixel shows:
  - alpha 0 where only a fully transparent part of a screen is in front;
  - alpha 1 where an opaque part covers it;
  - an alpha within 2/255 of the image alpha where a half-transparent part covers it.
- The output pixel rule applies on the direct canvas path, on the post chain (`antiAliasing: 'fxaa'`, and a visible haze), and in a `cameraScreenshot` PNG (straight alpha after `screenshot.ts`).
R16. A screen is a viewport pick target. The transform gizmo moves, rotates, and scales it.

### Editor

R17. The Add menu has **Screen** after **Prop**. It creates `{ kind: 'screen', name: 'Screen', visible: true, content: { kind: 'image', assetId: null } }` with an identity transform. A second screen is `Screen 2`, as for the other kinds. The Add item and Duplicate (`budgetFull` in `Hierarchy.svelte`) are disabled at 16 screens or at the 64-entity scene limit. The Hierarchy row icon is the image icon of the icon set that the Hierarchy uses.
R18. The Hierarchy groups screens under **Screens**, after **Props** (`asset-groups.ts`).
R19. The Inspector for a screen shows Name, Visible, Transform, and a **Screen** section with an **Image** field. The field has:
- a select of the image records;
- the `Import file…` row;
- the load status;
- the failure message.

It has the same form as the Prop **Source** field. A record option sends `setScreenImage`. `Import file…` runs `import_image` through a new `chooseImage` handler in `EditorApp.svelte`. A returned record sends `setScreenImage` for that screen only. A cancelled dialog keeps the value. An import error shows the host message, or `Could not import image` when it has none. An unknown `assetId` shows `Missing image`. The Inspector reset (default `assetId: null`) and the section index cover the section (B17). The Assets list shows image records with their format, as it does for the other records.
R20. Regression tests: the Prop and Environment source selects (`sceneSourceOptions`) and the character model field do not list image records. The Screen select lists only image records.

### MCP and files

R21. MCP `scene_patch` accepts `createEntity` with a screen and `setScreenImage`. `asset_list` returns image summaries with `kind: 'image'`. The `asset_list` description names `setScreenImage`, and the `scene_patch` description says how to add a screen. There is no MCP image import.
R22. Save As and Open keep each screen and its content. A screen whose `assetId` is not in the library (for example, a show from another computer) opens and shows `Missing image`.

## A — Approach

Add one asset kind and one entity kind. Reuse the prop paths at each step. The host checks only the signature and the header of the image. The renderer decodes it with the browser in one call, already scaled to the profile limit. A screen is one unlit quad. All screens with the same asset in one client share one texture. `content` is a union now, so B29 to B31 add members and do not change the entity shape. No image data goes through Tauri IPC. The renderer reads the bytes over `GET /assets/{id}`, as for models.

## N — Norms

- Use `@oshi-connect/ui` controls.
- Keep UI copy to the labels in R3, R13, R17 to R19, and R22.
- Write prose in ASD-STE100.
- Use pnpm.
- Keep functional TypeScript and plain data.
- Follow the one-operation-for-each-property pattern.
- Do not commit third-party images.
- Store the image metadata as one nested group on the record (constitution rule 7).

## S — Safeguards

- Do not loosen the GLB trust checks. A GLB or VRM record keeps `validate_glb` and `inspectContainer`.
- Do not send image bytes or decoded pixels through Tauri IPC.
- Do not change the look of avatars, props, the environment, or the lights. A scene without a screen renders the same pixels as before.
- Do not add a Rust image decoding crate or a new vendor.
- Do not claim these from this slice: GIF or WebP animation, video, web pages, capture, Bend, Thickness, Crop, Corner Radius, Tint, Chroma Key, or Windows support.
- An old build does not open a show with a screen. Record this in the evidence.
