# REASONS: YouTube chat events

Analysis: [YouTube chat events](../analysis/2026-10-27-youtube-chat-events.md). Issues: [#197](https://github.com/danirukun/opensekai/issues/197) (parity BP-16), [#87](https://github.com/danirukun/opensekai/issues/87) (BP-07, the parent). Queue bundle B25.

## R — Requirements

1. **Gate first.** The implementation starts with the client module and its tests (requirements 4 to 9) and the live gate of issue #197: resolve a watch URL, a `youtu.be` URL, and an `@handle` URL to the live video ID (the three gate links use these three forms, one each); receive chat for 30 minutes on 3 different public live streams without an error, a duplicate, or a gap at a forced reconnect; parse one fixture of each action type; and keep each poll wait at or above the server `timeoutMs`. The gate runs as an ignored Rust test (`youtube_live_gate`, `#[ignore]`) that reads the stream links from `OPENSEKAI_YOUTUBE_GATE_LINKS` and prints the counts. It runs in the cloud when the network reaches YouTube, else on the owner computer. When two of three streams fail, the run stops before requirement 10, comments the result and the question (ship option (b) with a user key, or wait) on #197, and adds `agent:blocked` and `question`.
2. **Settings store.** The host keeps one file `<app local data>/settings/integrations.json` with `{youtube: {link: string | null}}`, written with a temporary file and a rename. A missing file means `link: null`. A file that fails to parse or validate is logged and treated as `link: null`, and the host does not overwrite it until the next `integrationsSet`. The link is never in a show, a scene, a frame, or a Blueprint file.
3. **Call.** A new method `integrationsSet {youtube: {link: string | null}}` with the Edit capability. The host answers it itself, as `appStatus`; it is never relayed to the publisher. `link` is at most 2,048 characters. `null` or an empty string after trim disconnects and stores `null`. Any other value must pass requirement 4, or the reply is `INVALID_INPUT` with the reason in the message, and the stored link and the running client do not change. A valid link is stored, the running client stops, the seen-ID set clears, and a new client starts. The reply data is the new `youtube` status of requirement 11 (`ResultSchemas.integrationsSet` is `YouTubeStatusSchema`). TypeScript and Rust check the same params shape; only Rust parses the link. The Edit capability is set in TypeScript `requiredCapability` and in the Rust capability match in `service/router.rs`, and the method is added to the Rust method lists in `crates/contracts/src/lib.rs`.
4. **Link parsing.** The pure function `parse_stream_link(text) -> Result<StreamTarget, LinkError>` trims the text and accepts the scheme `https`, `http`, or none, and the hosts `youtube.com`, `www.youtube.com`, `m.youtube.com`, and `youtu.be` (case-insensitive host). `StreamTarget::Video(id)` comes from `/watch?v=<id>` (other query parameters ignored), `youtu.be/<id>`, and `/live/<id>`; `id` is exactly 11 characters of `[A-Za-z0-9_-]`. `StreamTarget::Channel(path)` comes from `/@<handle>` (handle `[A-Za-z0-9._-]{3,30}`), `/channel/UC<22 characters of [A-Za-z0-9_-]>`, and `/c/<name>` (name `[A-Za-z0-9._-]{1,100}`), with a trailing `/live`, `/featured`, or `/` removed. A path with any other character (for example `/`, `?`, `#`, `%`, or `..` inside the handle or name) is rejected. The host builds the fetch URL `https://www.youtube.com<path>/live` only from these checked parts. Any other input is a `LinkError` with a short reason (`Not a YouTube link`, `No video ID`, `Not a channel or video link`).
5. **Resolve.** For a channel target the host GETs `<channel>/live`. When the page has `<link rel="canonical" href="https://www.youtube.com/watch?v=<id>">`, `<id>` is not the last ended video ID of this link, and the page does not mark the video as finished (`isLiveNow` false with an end time), the video ID is `<id>`. Else the state is `waiting` and the host checks again after 60 s. For a video target, the ID is direct.
6. **Bootstrap.** The host GETs `https://www.youtube.com/live_chat?v=<id>&is_popout=1`. It reads `INNERTUBE_API_KEY`, `INNERTUBE_CONTEXT`, and the client version from `ytcfg.set(...)`, and the first continuation from `ytInitialData` `contents.liveChatRenderer`, choosing the "Live chat" (all messages) option of the view selector when the page offers it, never "Top chat". A page without a live chat renderer gives `waiting` for a video link and a channel link, with a new try after 60 s. A live chat renderer with `isReplay` true is a finished stream: the state is `ended` (requirement 7a), never `live`. A redirect to `consent.youtube.com` gives `error` with `Consent page`. The chat items in `ytInitialData` go through requirement 8 as the backlog.
7. **Poll.** The host POSTs `https://www.youtube.com/youtubei/v1/live_chat/get_live_chat?key=<key>&prettyPrint=false` with `{context, continuation}`, where `context.client.hl` is `en` and `context.client.gl` is `US`. It reads `continuationContents.liveChatContinuation.actions[]` and the next continuation from `invalidationContinuationData`, `timedContinuationData`, or `reloadContinuationData`, with `timeoutMs`. The next poll waits `poll_wait(timeoutMs) = max(timeoutMs, 1000)` ms, or 1,000 ms when `timeoutMs` is absent. There is no upper clamp, so a wait is never below the server value. Only an explicit end signal (a `liveChatEndedRenderer`, or the chat-ended action) gives `ended`. A reply without a next continuation and without an end signal is an error with `Chat page changed` (requirement 13).
7a. **End.** In `ended`, a video link stays `ended` and makes no more requests until the link changes. A channel link stores the ended video ID as the last ended video ID, goes back to `waiting` after 60 s, and checks `/live` every 60 s (requirement 5), so the same ended video does not resolve again.
8. **Actions.** The pure function `parse_actions(json) -> Vec<ChatItem>` maps `addChatItemAction.item` renderers. Each `ChatItem` has the renderer `id` and `timestampUsec`:
   - `liveChatTextMessageRenderer` → `chat`: `message`, `username`, `userChannelId`, `avatarUrl`, `isMember`, `isModerator`, `isOwner`, `isVerified`.
   - `liveChatPaidMessageRenderer` → `superChat`: `message` (empty when none), `username`, `userChannelId`, `avatarUrl`, `amount` (the display text), `amountMicros`, `currency`, `tierColor`.
   - `liveChatPaidStickerRenderer` → `superSticker`: `stickerName` (the accessibility label), `stickerImageUrl`, `username`, `userChannelId`, `amount`, `currency`.
   - `liveChatMembershipItemRenderer` with `headerPrimaryText` holding a month count → `memberMilestone`: `username`, `userChannelId`, `months`, `message`. Without it → `newMember`: `username`, `userChannelId`, `avatarUrl`, `levelName` (the `headerSubtext` text after "Welcome to " and before "!", or the whole text).
   - `liveChatSponsorshipsGiftPurchaseAnnouncementRenderer` → `giftMemberships`: `username`, `userChannelId`, `count` (the integer in the header primary text).
   - `liveChatSponsorshipsGiftRedemptionAnnouncementRenderer` → counted in `redemptions`, no event.
   - Any other renderer or action is skipped and counted in `skipped`.
   Text: the runs join in order; a run with `text` gives the text; a standard emoji (`emoji.isCustomEmoji` false) gives its `emojiId`; a custom emoji gives its first `shortcuts` entry. Badges: `MODERATOR`, `OWNER`, and `VERIFIED` icon types set the flags; a badge with `customThumbnail` sets `isMember`. Image URLs take the last (largest) thumbnail and add `https:` to a `//` URL. `tierColor` is `#RRGGBB` from `bodyBackgroundColor` (ARGB). Strings are cut to 1,024 characters (`MAX_BLUEPRINT_STRING_LENGTH`), names and IDs to 256. A renderer without `id` is skipped.
9. **Amounts.** The pure function `parse_amount(text) -> (amount_micros: i64, currency: String)` splits the symbol or code from the number and maps the symbol or code to a currency first. For a currency without minor units (JPY, KRW, VND, CLP, ISK, and the other ISO 4217 zero-decimal codes in the table), each `,` and `.` is a group separator. For other currencies, the last `,` or `.` is the decimal separator only when exactly one or two digits follow it to the end; every other separator is a group separator. It maps the symbol with one table that holds at least `$` USD, `CA$` CAD, `A$` AUD, `NZ$` NZD, `HK$` HKD, `NT$` TWD, `MX$` MXN, `R$` BRL, `€` EUR, `£` GBP, `¥` JPY, `￥` JPY, `CN¥` CNY (YouTube writes the yuan as `CN¥`, so a bare `¥` is JPY), `₩` KRW, `₹` INR, `₱` PHP, `₫` VND, `₪` ILS, `CHF`, `SEK`, `NOK`, `DKK`, `PLN`, `RUB`, `TRY`, `ZAR`, `SGD`, `MYR`, `IDR`, `THB`, `ARS`, `CLP`, `COP`, `PEN`, `CZK`, `HUF`, `RON`, `BGN`, `HRK`, `ISK`, `SAR`, `AED`, `QAR`, `EGP`, `NGN`, `KES`. A three-letter code is used as is. An unknown symbol gives `(0, <symbol text>)`.
10. **Events to the session.** For each new chat item (requirement 12) the host makes one `YouTubeEvent` and queues it (at most 256; on overflow it drops the oldest and counts `dropped`). Each change of the youtube state between `waiting`, `live`, `ended`, and `error` queues one `{kind: 'status', status}` event. The host queues events only while the listened graphs have a YouTube node: the session reports `youtube: true` in the `blueprintEdit` reply and the `blueprintInspect` snapshot, through the same path as `devices`, and the host drops (and does not count) events while that flag is false. Each clock takes at most 8 events in `input.youtube: {events: YouTubeEvent[]}` (1 to 8), and only as many from the queue front as fit a YouTube budget of 24 KiB of serialized JSON; the other events stay at the queue front for the next clock. A clock with `input.youtube` uses the large limit in `clockByteLimit` and `clock_byte_limit`. `clock_message` trims tracking samples first and never drops `input`; a vector with 8 events of maximum-length multi-byte strings, full device input, and tracking samples proves that the clock fits. The session turns each event into `BlueprintEvent {kind: 'youtube', event}` after the device events and before the tracking triggers, in queue order, and runs the matching nodes of the enabled graphs with `RunEnv.youtube` set to the event. These runs share the existing step budget (`TICK_EFFECTS` 64, `TICK_VISITS` 1,024); a run over the budget fails with the existing limit error, as a device run does.
11. **Status.** `appStatus` gets an optional `youtube: {link: string | null, state, error: string | null, videoId: string | null, items: number, skipped: number, redemptions: number, dropped: number}`. `state` is `notConnected` (no link), `waiting`, `live`, `ended`, or `error`. `error` has a text only in `error` (`Consent page`, `HTTP <code>`, `Chat page changed`, `Network`, or the link reason). The counts are since the current link was set. `dropped` counts queue overflow only. TypeScript and Rust check the same shape.
12. **Seen IDs and backlog.** The host keeps the last 4,096 item IDs of the current link in a bounded set (`SeenIds`, insertion order eviction). An item with a seen ID is dropped. On the first bootstrap of a link, the backlog items are marked seen and are not queued. The host keeps `latestUsec`, the largest server `timestampUsec` of any item seen for the link (the host clock is never compared with server time). On a later bootstrap (a reconnect), each unseen backlog item with `timestampUsec` above `latestUsec` minus 5 s is queued in timestamp order; older unseen items are marked seen and not queued.
13. **Reconnect.** A network error, an HTTP status other than 200, a body over the size limit, or a parse error that leaves no next continuation puts the state in `error` and waits `backoff(attempt, r) = max(1 s, min(60 s, 1 s × 2^attempt) × (0.5 + 0.5 r))` with `r` uniform in `[0, 1)`, then bootstraps again (requirement 6). A successful poll resets `attempt` to 0 and sets `live`. Thus after network loss the state returns to `live` and requirement 12 prevents duplicates.
14. **HTTP client.** One `reqwest::Client` for each link, with a cookie store, the cookie `SOCS=CAI` for `.youtube.com`, a fixed desktop browser `User-Agent`, a 15 s timeout, at most 5 redirects that must stay on `youtube.com` hosts (else `error`), and body limits of 4 MiB for a page and 1 MiB for a poll reply. The base URL is a field of the client so the integration test can point it at a local mock; the app always uses `https://www.youtube.com`. Only the host makes these requests; no WebView, renderer, MCP client, or extension gets the client.
15. **Blueprint nodes.** Category `YouTube`. Each node has no settings, no inputs, and outputs `flow` plus the data below. The data comes from `RunEnv.youtube` when the run started from a matching event, else the type default.

    | Type | Label | Data outputs |
    | --- | --- | --- |
    | `youtube.chat` | On YouTube Chat Received | `message`, `username`, `userChannelId`, `avatarUrl` (string); `isMember`, `isModerator`, `isOwner`, `isVerified` (boolean) |
    | `youtube.superChat` | On YouTube Super Chat Received | `message`, `username`, `userChannelId`, `avatarUrl`, `amount`, `currency`, `tierColor` (string); `amountMicros` (number) |
    | `youtube.superSticker` | On YouTube Super Sticker Received | `stickerName`, `stickerImageUrl`, `username`, `userChannelId`, `amount`, `currency` (string) |
    | `youtube.newMember` | On YouTube New Member | `username`, `userChannelId`, `avatarUrl`, `levelName` (string) |
    | `youtube.memberMilestone` | On YouTube Member Milestone | `username`, `userChannelId`, `message` (string); `months` (integer) |
    | `youtube.giftMemberships` | On YouTube Gift Memberships | `username`, `userChannelId` (string); `count` (integer) |
    | `youtube.status` | On YouTube Stream Status Changed | `status` (string: `waiting`, `live`, `ended`, `error`) |

    The port labels follow the existing label rule of the editor. The node audit gets one row for each type, with the Warudo node name where Warudo has one.
16. **Settings panel.** The Editor rail gets a **Settings** button (the kit `Button`, a lucide icon) after Resources. The panel has the heading `Settings`, one section `Integrations`, and in it the group `YouTube` with the kit `Input` labelled `Stream link`, one status line, and one help line: `Reads the public chat page. Not an official YouTube API.` The issue asks for this ToS help text; it is the one exception to constitution principle 1 in this slice, and the owner decides it in the contract review. The status line text is `Not connected`, `Waiting for stream`, `Live`, `Chat ended`, or `Error: <reason>`, from `appStatus.youtube`, which the editor poll already reads. The input commits on Enter and on blur when its value differs from the stored link. An `INVALID_INPUT` reply shows `Error: <message>` as the status line until the next commit. No other control, pill, badge, or card.
17. **MCP.** One new tool `youtube_link_set {link: string | null}` maps to `integrationsSet`. `app_status` returns `youtube`. The `blueprint_*` tools list the new node types through the catalog, without code changes.
18. **Shutdown.** The client task stops when the link changes or clears, and on app exit, with no request after the stop. A stop during a wait does not wait for the timer, and a stop during a request cancels the request (the task selects on a stop signal).
19. **Known gaps, not in this slice:** option (b) (Data API key) as a fallback, replay of a finished stream, a node for each gift redemption, a recent-event list in the editor, Twitch, Bilibili, and other platforms, redeems (BP-07 parent), the macOS latency check (an owner check), and Windows.

## E — Entities

- `StreamTarget` (Rust): `Video(String)` or `Channel(String)`.
- `YouTubeSettings`: `{link: string | null}`; file `{youtube: YouTubeSettings}`.
- `IntegrationsSetParams`: `{youtube: {link: string | null}}` (zod and Rust; `link` at most 2,048 characters).
- `YouTubeEvent` (zod `YouTubeEventSchema` and Rust mirror), discriminated by `kind`: `chat`, `superChat`, `superSticker`, `newMember`, `memberMilestone`, `giftMemberships` with the fields of requirement 8 plus `id` (at most 256 characters), and `status` with `status: 'waiting' | 'live' | 'ended' | 'error'`. Strings follow the length limits of requirement 8. `months` and `count` are integers from 0 to 10,000. `amountMicros` is a safe integer at or above 0.
- `InputUpdateSchema` gains `youtube: {events: YouTubeEvent[] (1 to 8)}` (optional); the "input update is empty" refine counts it.
- `blueprintEdit` result and `BlueprintInspect` snapshot gain `youtube?: true`.
- `YouTubeStatus`: the shape of requirement 11. `AppStatusSchema` gains `youtube?: YouTubeStatus`.
- `ChatItem` (Rust): `{id, timestamp_usec, event: YouTubeEvent}`.
- `SeenIds` (Rust): a bounded set of 4,096 IDs.
- `BlueprintEvent` gains `{kind: 'youtube'; event: YouTubeEvent}`. `RunEnv` gains `youtube?: YouTubeEvent`.

## S — Safeguards

- Do not poll faster than `poll_wait` or retry faster than `backoff`. Do not open more than one client.
- Do not send a request to a host other than `youtube.com` hosts. Do not follow a redirect off them.
- Do not give the HTTP client, cookies, or raw responses to a WebView, renderer, MCP client, Blueprint, or extension. The session gets only typed events.
- Do not store the link in a show, a scene, or a Blueprint file. Do not store chat content on disk.
- Do not start a Blueprint for a message from before the first connection to a link, or twice for one item ID.
- Do not commit recorded fixtures with real names, channel IDs, avatar URLs, or messages; replace them with synthetic values.
- Do not add a sign-in, an API key field, or another vendor in this slice.
- Do not claim BP-07 or the macOS path from the cloud. The owner checks on macOS: a chat message in a public live stream starts On YouTube Chat Received within 10 s with the right fields, a network loss and return gives no duplicate and `Live` again, the Settings panel in the Tauri window, and Super Chat or membership events when a test stream can receive them (`accept:local`).
