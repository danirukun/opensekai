# REASONS: Video screens

Date: 2026-11-08. Scope: MED-02 slice 1. A Screen whose content is one MP4 or WebM video from the asset library. The session owns the playback position. Both renderer instances play the video in sync. The OBS page plays the audio. Each renderer instance reports a codec that it cannot decode. Analysis: [video screens](../analysis/2026-11-08-video-screens.md). Issue: [GitHub #60](https://github.com/danirukun/opensekai/issues/60). Base: [image screens](2026-11-04-image-screens.md) (B28).

In this contract, "1 frame" is 1/60 s (16.67 ms), the session clock step.

## R — Requirements

### Asset record

R1. `AssetRecord.format` adds `mp4` and `webm` in TypeScript (zod) and Rust. The record adds the optional group `video: { width, height, durationMs, videoCodec, audioCodec, alpha }`:
- `width` and `height`: the display size, integers 1 to 4096.
- `durationMs`: integer 1 to 14,400,000 (4 hours).
- `videoCodec`: `h264 | hevc | vp8 | vp9 | av1`.
- `audioCodec`: `aac | mp3 | opus | vorbis | null`.
- `alpha`: boolean.

TypeScript (`AssetRecordSchema`) and Rust (`AssetRecord` `Validate`) apply the same cross-field rules:
- A video format needs `video`, an ID with the `video_` prefix, `bytes` at most 268,435,456 (256 MiB), `expressions` empty, no `image`, and no `rig`, `eyeBones`, or `meshes`.
- `mp4` allows `videoCodec` `h264`, `hevc`, or `av1` and `audioCodec` `aac`, `mp3`, `opus`, or `null`. `webm` allows `vp8`, `vp9`, or `av1` and `opus`, `vorbis`, or `null`.
- `alpha` is true only for `webm` with `vp8` or `vp9`.
- Any other format has no `video` and no `video_` ID.
- Old records validate without change.

`fixtures/protocol/video-records.json` holds valid and invalid records, and a test on each side reads it (as `image-records.json` does).

R2. The ID of a video record is `video_` plus the SHA-256 of the stored bytes. The library file extension is `.mp4` or `.webm`. The registry library load uses the same table as B28 R2. `AssetSummary.kind` adds `video` (TypeScript and Rust), from the `video_` prefix. A video record has `licenseLabel: "User supplied"`, `sourceUrl: null`, `importerVersion: 1`, and no `credits`.

### Import

R3. A new editor-only Tauri command `import_video` opens a native dialog. The title is `Import video`. The filter is `Video` with `mp4`, `m4v`, and `webm` (no filter label on macOS, as at the `import_image` filter in `lib.rs`). The frontend never sends a path. The command returns `{ record, name }` or `null` for a cancel, as `import_image` does, and the host sends the `asset-record` event. The command is in each place that `import_image` is (B28 R3): `build.rs`, `permissions/autogenerated/import_video.toml`, `capabilities/main.json`, `generate_handler!`, the exact permission list test, the ports trait in `bootstrap.rs`, `DesktopState::import_video` with the same `AssetStep` hooks, and the `invoke` site in `EditorApp.svelte`.

R4. `assets/video.rs` has one pure function `parse_video(bytes) -> Result<VideoHeader, AppError>` (format, width, height, durationMs, videoCodec, audioCodec, alpha). It reads container structure only. It does not decode a frame. It uses no new crate. It finds the type from the signature only, not from the file extension. Each rule reads only inside the buffer and checks each length before use. Each failure is `INVALID_INPUT` with a message that names the type and the reason.

**MP4 (ISO BMFF):**
- The first box is `ftyp`. Its major brand is not `qt  `.
- A box size is a big-endian u32 after which the type follows. Size 1 reads a u64 large size after the type. Size 0 runs to the end of its parent. A size below the header size, or past the parent end, is a failure.
- Walk the top-level boxes across the whole file. Exactly one `moov` is necessary. A box with an unknown type is skipped.
- `moov/mvhd`: version 0 has the timescale (u32) at body offset 12 and the duration (u32) at 16. Version 1 has the timescale (u32) at 20 and the duration (u64) at 24. Body offsets count from the end of the box header and include the version and flags. A timescale of 0, a duration of 0, or a duration with all bits set fails with `Video has no duration`. A fragmented MP4 without a duration is not supported.
- For each `moov/trak`: `mdia/hdlr` gives the handler (`vide` or `soun`), and `mdia/minf/stbl/stsd` gives the first sample entry.
- The first `vide` track is the video. Its sample entry `avc1` or `avc3` is `h264`, `hvc1` or `hev1` is `hevc`, and `av01` is `av1`. Another entry (for example `mp4v`, `vp09`, or an encrypted `encv`) fails with `Video codec not supported`.
- The coded size is the width and height (u16) of the visual sample entry. Each must be 1 to 4096.
- Its `tkhd` (version 0 or 1) gives the width and height (16.16 fixed point, integer part) and the 3 × 3 matrix. The matrix must be one of the four turns (0, 90, 180, or 270 degrees, with no mirror and a scale of 1). 90 and 270 swap width and height. 0 and 180 do not. Another matrix is a failure. The display size is the turned `tkhd` size. When the `tkhd` size is 0, the display size is the turned coded size.
- The first `soun` track is the audio. Its `mp4a` entry contains an `esds` box. Its `DecoderConfigDescriptor` (tag 0x04) object type 0x40 is `aac`, and 0x69 or 0x6B is `mp3`. An `Opus` entry is `opus`. Another entry fails with `Audio codec not supported`. No `soun` track gives `null`.
- Each `dref` entry in each track must have the self-contained flag (flags bit 0). An entry without it (an external data reference) is a failure.
- `alpha` is false.

**WebM (Matroska with DocType `webm`):**
- The file starts with the EBML ID `1A 45 DF A3`. The EBML header `DocType` is `webm`. Another DocType (for example `matroska`) is a failure.
- Element IDs and sizes use the EBML variable-length rules (IDs up to 4 bytes, sizes up to 8 bytes). An unknown size is allowed only for `Segment` and `Cluster`.
- In `Segment`, walk the children until `Info` and `Tracks` are read. The walk reads at most the first 16 MiB. A first `Cluster` before both are read fails with `Video header not found`.
- `Info` gives `TimecodeScale` (default 1,000,000 ns) and `Duration` (a 4- or 8-byte float). A missing, non-finite, or non-positive duration fails with `Video has no duration`. So a live MediaRecorder file without a duration is not supported.
- The first `TrackEntry` with `TrackType` 1 is the video. `CodecID` `V_VP8` is `vp8`, `V_VP9` is `vp9`, and `V_AV1` is `av1`. Another one fails with `Video codec not supported`.
- Its `Video` element gives the coded size `PixelWidth` and `PixelHeight`. Each must be 1 to 4096. The display size is `DisplayWidth` and `DisplayHeight` when both are present and `DisplayUnit` is 0 (or absent). Otherwise it is the coded size. `AlphaMode` 1 sets `alpha`.
- The first `TrackEntry` with `TrackType` 2 is the audio: `A_OPUS` is `opus` and `A_VORBIS` is `vorbis`. Another one fails with `Audio codec not supported`. No audio track gives `null`.
- A `ContentEncodings` element in the video or the audio track (encryption or compression) is a failure.

For both types: no video track fails with `Video has no video track`. A display size or duration outside R1 is a failure. A file whose audio codec is not supported fails as a whole. A muted import of such a file is not in this slice.

R5. The import first checks the file metadata length. A file above 256 MiB fails with `INVALID_INPUT` and the message `Video is larger than 256 MiB`. `stage_video` copies the source to a temporary library file in 1 MiB chunks, hashes the chunks, and stops with the same failure when the copy passes 256 MiB. Then it reads the temporary copy (not the source) into memory one time, runs `parse_video`, and drops the buffer. So the hash and the parse use the same bytes. The record name is the file stem, cut by `bounded_name`, or `Video` when the stem is empty. The same bytes return the existing record through `AssetRegistry::commit`. `stage_video` stages without the registry lock, as `stage_image` does.

### Serve and trust

R6. `read_located` adds a branch for the video formats. It reads the full file, checks the size and the SHA-256 (as now), and runs `parse_video`. The detected values must equal `record.video` and `record.format`. `GET /assets/{id}` answers `video/mp4` or `video/webm` with `x-content-type-options: nosniff`. The service sends no `Range` or `accept-ranges` response in this slice. The full read at each serve is a known cost (up to 256 MiB of hash for each renderer load). R15 limits the retries.

R7. `ARCHITECTURE.md` changes in the same commit. The trust rule now names a third container type: one MP4 or WebM file whose container structure the host checks at import and at serve (`parse_video`), with no external data reference, and whose signature the renderer checks at load (R13). Asset path steps 1, 2, and 4 name the video import, the serve check, and the video load. The renderer paragraph names the playback rule (R12 to R15) and the OBS audio rule (R16).

### Scene and session

R8. `ScreenContentSchema` adds `{ kind: 'video', assetId: Id | null, autoPlay: boolean, loop: boolean, volume: number }` (`volume` 0 to 1) in TypeScript and the Rust `ScreenContent`. A scene has at most 4 screens with video content (`LIMITS.videoScreens` in the `SceneViewSchema` refine and `MAX_VIDEO_SCREENS` in the Rust `SceneView::validate`), inside the B28 limit of 16 screens. A show without a video screen validates without change. A patch that makes a fifth video screen (by `setScreenVideo`, `createEntity`, or Duplicate) fails the scene check with `INVALID_INPUT`.

R9. The operation `setScreenVideo { entityId, video: { assetId, autoPlay, loop, volume } }` sets `content` to `{ kind: 'video', ...video }`. `setScreenImage` (B28 R9) sets image content on a screen with video content. Both fail with `NOT_FOUND` for an unknown entity and with `INVALID_INPUT` for an entity that is not a screen. The operation is in `PatchOpSchema`, `LivePatchOp`, and the Rust `PatchOp`. It commits like the other scene operations. The session does not check that the asset exists or that it is a video (as B28 R9).

R10. The runtime operation `controlScreenVideo { entityId, action: 'play' | 'pause' | 'restart' }` is in `PatchOpSchema` and the Rust `PatchOp`, so `scenePatch` and MCP `scene_patch` carry it. It never commits. The session handles it in `applyPatch` (`session.ts`) as follows:
- Before the commit, the session takes the control operations out of the operation list (as `resolveCalibrations` changes the list).
- It applies the other operations and commits them as now, with the `expectedRevision` check.
- Then it checks each control operation against the committed scene. It fails with `NOT_FOUND` for an unknown entity and `INVALID_INPUT` for an entity that is not a screen with video content. A control operation can target an entity that the same patch creates.
- A patch is atomic. When a control operation fails, the session checks it before the commit and rejects the full patch with no commit.
- A patch with only control operations skips the commit and the `expectedRevision` check, does not change the revision, and replies with the current revision.
- After a successful patch, the session applies the control operations to the runtime entries (R11) in their order.

R11. The session keeps one runtime entry for each screen with video content: `{ playing, anchorMs, offsetMs }`. `anchorMs` is the session `elapsedMs` at the last play or restart. `offsetMs` is the position at that time. The position is `offsetMs + (elapsedMs − anchorMs)` while playing and `offsetMs` while paused.
- A new entry starts with `offsetMs` 0 and `playing` equal to `autoPlay`. A new entry starts when a screen gets video content (`setScreenVideo` on another content kind, or `createEntity`, which is also the Duplicate path of `model.duplicateEntity`), when its `assetId` changes, and when a show opens (`replaceScene`).
- A change of `autoPlay`, `loop`, or `volume` does not change the entry.
- `play` sets `anchorMs` to now and keeps `offsetMs`. `pause` stores the current position in `offsetMs`. `restart` sets `offsetMs` to 0 and `anchorMs` to now and keeps `playing`.
- The entry is removed when the screen is deleted or its content is no longer video.
- The entry is never saved or put in a show file.
- The clock runs from the start of the entry, also while a renderer loads the file. A short clip without loop can end before a renderer draws it. Restart plays it again. This is intended: all renderers show the same position.

Each frame has the optional field `screenPlayback: [{ entityId, playing, positionMs }]` for each screen with video content and a non-null `assetId` (at most `LIMITS.videoScreens` entries, unique IDs, `positionMs` a non-negative integer). `positionMs` is not wrapped: the renderer applies `loop` (from `frame.scene`) and the duration (R14). `RuntimeFrameSchema` and the Rust `RuntimeFrame` both accept the field (both are strict). A frame without a video screen has no field.

### Renderer

There are two renderer instances: the OBS page (`apps/output`, output `output_main`) and `preview_main` in the Editor window (`bootstrap.ts`). The scene pane preview, the editor viewport, and `cameraScreenshot` all use `preview_main`.

R12. Each renderer instance draws one quad for each visible screen with video content, a non-null `assetId`, and a loaded video. The quad rules of B28 R11 apply: 1 m high, `width / height` m wide, local XY plane, facing +Z, `DoubleSide`, the front upright and not mirrored, and the back mirrored. `width` and `height` are `videoWidth` and `videoHeight` of the loaded element. The material rules of B28 R14 apply: unlit, `toneMapped: false`, no shadows, and not in a light group.

R13. Video loading:
- The renderer reads the bytes with `readAsset`. `readVideoInfo(bytes)` in `video-screen.ts` reads the format, the codec family, the RFC 6381 codec string, the audio codec, and the alpha flag, with the R4 rules for the boxes and elements that it needs (`avcC`, `hvcC`, and `av1C` for the MP4 codec string; `CodecID`, `CodecPrivate`, and `AlphaMode` for WebM). It returns null for a GLB, a VRM, an image, or another file. For each test file of Operation 1, its result must equal `fixtures/video/expected.json`, which the host test also reads. The renderer has no record; the host check of R6 makes sure that the file equals the record.
- It makes one `Blob` (type `video/mp4` or `video/webm`) and one object URL for each asset in one renderer instance, and it drops the read buffer. When no screen uses the asset, it revokes the URL. The asset IDs are in the `used` set and in `retainOnly`.
- It makes one `HTMLVideoElement` for each screen, because two screens with the same asset have their own positions. The element has `playsInline`, `preload: 'auto'`, `loop` equal to the content `loop`, no `crossOrigin`, and is not in the DOM tree. Its `muted` and `volume` follow R16.
- The texture is a three.js `VideoTexture` with `colorSpace` sRGB and the UV and flip rule of B28 R12, so the front is upright. Operation 5 step 1 checks this on WebGL 2 and WebGPU before other renderer work.
- The load succeeds at the element `loadeddata` event. An element `error` event, or no `loadeddata` within 10 s, is a failure.
- While the screen is not visible, the element is paused and the texture does not update.

R14. Playback sync, on each applied frame, for each screen with a `screenPlayback` entry and a loaded element:
- `duration` is the element `duration` in ms. The target is `positionMs mod duration` when `loop` is true, and `min(positionMs, duration − 1 frame)` when it is false.
- When the entry is playing and the target is before the end, a paused element gets `play()`. When the entry is paused, or the end is reached without `loop`, the element gets `pause()`.
- When the distance between `currentTime` and the target is above 250 ms (with `loop`, the shorter way around the end), the renderer sets `currentTime` to the target. For a paused entry, the limit is 1 frame.
- The renderer does not change `playbackRate`. It does not start a second seek while a seek runs.
- A rejected `play()` promise gives the frame warning `Video playback blocked`. The renderer tries again on the next playing frame.
- `cameraScreenshot` draws the current texture. It does not wait for a seek.
- When the `preview_main` pump stops (the Preview toggle or the Assets tab), the instance pauses all its video elements. On the next applied frame, the rules above seek and play them again. A screenshot that wakes the pump can show the frame before that seek.
- The renderer exposes a test-only `videoSettled(entityId)` promise that resolves after the next `requestVideoFrameCallback` that follows a seek or a play. The headless checks use it. Production code does not wait on it.

R15. Load failures use the load jobs with a new `LoadRequest.kind` `video`. The failure messages are:
- `Video codec not supported: H.264`, `HEVC`, `VP8`, `VP9`, or `AV1`. Before the element loads, the renderer calls `navigator.mediaCapabilities.decodingInfo({ type: 'file', video: { contentType, width, height, bitrate: 1, framerate: 30 } })` with the full codec string. `supported: false` gives this message. Without `mediaCapabilities`, `canPlayType` answering `""` gives it. The element error codes `MEDIA_ERR_SRC_NOT_SUPPORTED` and `MEDIA_ERR_DECODE`, before or after `loadeddata`, also give it.
- `Audio codec not supported: AAC`, `MP3`, `Opus`, or `Vorbis`, when the same check for the audio codec gives `supported: false`. The video does not play.
- `Video failed to load` for each other failure: an unknown asset, a record of another kind, a null `readVideoInfo`, a read failure, and the 10 s timeout.

The frame warning is `Asset load failed: <message>`. The Inspector failure message is the `preview_main` message. A failure in the OBS page only is in the `output_main` frame acknowledgment warnings, so it is in `app_status` outputs and in the Assets list warnings (`collectWarnings`). A failed video job retries under the existing rule (a newer revision and 3 s), at most 3 times for one asset ID in one instance until the asset ID or the revision of its screen changes. A failure draws nothing for that screen and does not stop the other entities. A loading video gives the existing `Asset loading` warning. The asset ID branch in `renderer.ts` handles a video screen explicitly. A video is never read as a mesh or an image.

R16. Audio: only the OBS page plays audio. Its elements have `muted: false` and `volume` from the content. `preview_main` always sets `muted: true`. A video without an audio track plays the same way.

R17. Transparency: a video with `alpha` from `readVideoInfo` draws with the B28 R15 rules (`transparent: true`, normal blending, `depthWrite: false`, straight alpha). Each other video draws opaque. The output alpha rule of B28 R15 applies on the direct canvas path, on the post chain, and in a `cameraScreenshot` PNG.

R18. A video screen is a viewport pick target, and the transform gizmo moves, rotates, and scales it (as B28 R16).

### Editor

R19. The Inspector **Screen** section gets a **Content** select with **Image** and **Video** before the source field.
- Image shows the B28 **Image** field.
- Video shows a **Video** field with the same form: a select of the video records, the `Import file…` row, the load status, and the failure message. The empty option is `Choose video…`. An unknown `assetId` shows `Missing video`.
- Video also shows **Auto Play** (checkbox), **Loop** (checkbox), **Volume** (slider 0 to 1), one **Play** or **Pause** button, and **Restart**.
- The Play or Pause label follows the `playing` value of the latest `screenPlayback` entry. `bootstrap.ts` reads it from `preview.onFrame` before the preview pump (so it updates also when the pump stops) and gives it to `EditorApp.svelte`, which passes it to the Inspector. Without an entry, the button shows Play.
- A change of Content to Video sends `setScreenVideo` with `assetId: null`, `autoPlay: false`, `loop: true`, `volume: 1`. A change to Image sends `setScreenImage` with `assetId: null`. Content Video is disabled at the video screen limit, unless the screen has video content.
- A video record option, Auto Play, Loop, and Volume send `setScreenVideo` with the other values unchanged. Play, Pause, and Restart send `controlScreenVideo`. `model.ts` gets `setScreenVideo` and `controlScreenVideo` methods next to `setScreenImage`.
- `Import file…` runs `import_video` through a new `chooseVideo` handler in `EditorApp.svelte`. A returned record sends `setScreenVideo` for that screen only. A cancelled dialog keeps the value. An import error shows the host message, or `Could not import video` when it has none.
- Duplicate (`budgetFull` in `Hierarchy.svelte`) is disabled for a screen with video content at the video screen limit.
- The Inspector reset (B17) covers Content (default Image), Auto Play (false), Loop (true), and Volume (1). The section index covers the section.
- The Assets list shows video records with their format, video codec, and audio codec.

R20. Regression tests: the Prop, Environment, character, and Screen Image selects do not list video records. The Screen Video select lists only video records. The Add menu **Screen** item does not change (it still makes image content).

## A — Approach

Add one asset kind, one content member, one saved operation, and one runtime operation. Reuse the B28 paths at each step. The host checks the container structure and serves the file with the existing bearer read. The renderer plays the file from a `Blob` URL, so no token goes into a URL and the service needs no `Range` support. The session is the one clock: it puts the position on each frame, and each renderer instance corrects its element only when the drift is large. Only the OBS page makes sound. No video data goes through Tauri IPC.

## O — Operations

1. **Test media.** `scripts/make-test-videos.sh` makes these files with ffmpeg. Each file is at most 200 KB, 2 s long, 64 × 36 or smaller, tagged `-colorspace bt709 -color_primaries bt709 -color_trc bt709 -color_range tv`, with a solid color that changes each 0.5 s (red, green, blue, white), so a pixel read gives the position:
   - `h264-aac.mp4` (faststart), `h264-late-moov.mp4` (`moov` after `mdat`), `h264-turned.mp4` (90-degree matrix), `hevc.mp4`, `av1.mp4`
   - `vp8.webm`, `vp9-opus.webm`, `vp9-alpha.webm` (left half alpha 0, right half alpha 255), `av1.webm`

   The script records the ffmpeg version and the commands in `fixtures/video/README.md`. The files and `expected.json` are committed. The tests do not run ffmpeg.
2. **Contracts.** Schemas, types, the Rust mirror, the record fixture, and tests for the cross-field rules, the limits, the two operations, and the frame field.
3. **Host.**
   - Unit tests for `parse_video` on each test file against `expected.json` (size, duration within 1 frame of the ffmpeg value, codecs, alpha, the turned size).
   - Failure tests: each prefix of each file fails without a panic; a `qt  ` brand; a missing `moov`; a zero and an all-ones duration; an external `dref`; an `mp4v` entry; a mirrored matrix; a coded size above 4096 under a small `tkhd` size; a `matroska` DocType; a `Cluster` before `Tracks`; a WebM without `Duration`; a `ContentEncodings` track; an AC-3 audio track; no video track.
   - `stage_video`, the 256 MiB limit (with a sparse file), deduplication, library reload, and the serve checks (content type, a changed file, a record with another codec).
   - The permission list test.
4. **Session.** Unit tests for R8 to R11 with a stub clock: play, pause, restart, the position on frames, a new entry on asset change, `createEntity`, and `replaceScene`, no change on Loop, Volume, and Auto Play, removal on delete, a control-only patch with an old `expectedRevision` (no revision change), a mixed patch that creates and plays one screen, a mixed patch with a bad control operation (no commit), and the fifth video screen by each path.
5. **Renderer.**
   1. Spike first (go or no-go). On headless Chromium with WebGL 2 and WebGPU, draw `vp9-opus.webm` and `vp9-alpha.webm` with a `VideoTexture`. ### Benchmark gate

This slice does not change the benchmark. It gives the parts that the benchmark needs: a session-owned position and a restart operation. Before the concert benchmark uses a video screen, a benchmark slice must add: a restart of each video screen at `benchmarkStart`, the playback position in the run manifest, and the decode cost for each renderer instance (decoded and dropped video frames from `getVideoPlaybackQuality`). Until then, the parity line says that the benchmark subset is not done.

## S — Safeguards

- Do not loosen the GLB or image trust checks.
- Do not put a token in a URL. Do not add a `Range` endpoint in this slice.
- Do not send video bytes, frames, or audio through Tauri IPC.
- Do not make a renderer the clock owner. A renderer never changes the session position.
- Do not change the look of a scene without a video screen. Its frames have no `screenPlayback` field.
- Do not add a Rust media crate, a native decoder, or a new vendor.
- Do not claim these from this slice: HEVC alpha, MOV or Matroska, streaming, the benchmark subset, Blueprint playback, audio in the Editor window, OBS audio sync, decode cost on a real GPU, or Windows support.
- An old build does not open a show with a video screen. Record this in the evidence.
