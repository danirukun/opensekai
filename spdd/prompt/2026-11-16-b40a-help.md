# B40a contract: contextual help

Date 2026-11-16 · Scope: Help buttons and handbook pages · Issue #184 (UX-06) · Analysis: `spdd/analysis/2026-11-16-b40a-help.md`

## R: Requirements
- R1. Each panel in the analysis table has one Help button at the right end of its header row.
- R2. A click opens the handbook page for the topic of that panel in the default browser.
- R3. The Properties Help button opens the topic of the selected entity kind. With no selection, it opens `scene`.
- R4. The start screen Help button opens `gettingStarted`.
- R5. The webview sends only a topic name. Rust builds the URL from a fixed table. An unknown topic gives `INVALID_INPUT` "Unknown help topic".
- R6. When the open fails, Rust gives `UNAVAILABLE` "Help unavailable". The editor shows the toast "Could not open help".
- R7. The window gets no `opener:` permission. MCP gets no help tool.
- R8. `docs/handbook/` has the 9 pages in the analysis table. Each anchor in the table exists as a heading.

## E: Entities
- `HelpTopic` (Rust enum, serde camelCase; TS string union): gettingStarted, scene, character, motionCapture, vmcSender, environment, prop, light, haze, screen, fpsCounter, camera, output, blueprints, resources, settings.
- `fixtures/protocol/help-topics.json`: the ordered topic list. Rust and TS both test against it.

## A: Approach
- Copy the fixed-table pattern from `templates.rs`. Copy the native-open pattern from `open_camera_settings`.
- `help_url(topic) -> &'static str` returns `https://github.com/danirukun/opensekai/blob/main/docs/handbook/<page>.md[#anchor]`.
- The Svelte `HelpButton` calls `invoke('open_help', {topic})`.

## S: Structure
- New: `apps/desktop/src-tauri/src/help.rs`, `apps/desktop/src/editor/help.ts`, `apps/desktop/src/components/HelpButton.svelte`, `apps/desktop/test/help.test.ts`, `fixtures/protocol/help-topics.json`, `docs/handbook/*.md` (9 files), `docs/evaluation/contextual-help/editor-check.mjs`.
- Changed: `src-tauri/src/lib.rs` (mod, `generate_handler!`, pinned test), `src-tauri/build.rs`, `src-tauri/capabilities/main.json` (`allow-open-help`), the 9 panel files, `ARCHITECTURE.md`, `docs/warudo-parity.md`.

## O: Operations
- `open_help(window, topic: String) -> Result<(), AppError>`: check the window label, parse the name with `parse_topic` (an unknown name gives the R5 error), then `app.opener().open_url(help_url(topic), None::<&str>)`. The argument is a string because a Tauri argument that does not deserialize gives a plain string error, not an `AppError`.
- `topicForKind(kind: EntityKind | null): HelpTopic` is a pure function.
- `HelpButton` props are `{ topic: HelpTopic }`. It uses kit `Button variant="ghost" size="sm"`, `CircleQuestionMark size={16}`, `title="Help"` and a `sr-only` "Help" label. It is always enabled.

## N: Norms
- UI copy restraint: icon only, no label text, no badge.
- Pages use STE. They contain no screenshots and claim only verified behavior.
- No agent attribution.

## S: Safeguards
- No `opener:` permission. The pinned test still asserts this.
- The URL never comes from the webview.
- A Rust test checks that every topic URL starts with the fixed GitHub prefix, and that each anchor heading exists in its page file.
- TS and Rust topic lists are tested equal to the shared fixture.
