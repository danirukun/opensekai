# REASONS: Character mesh toggles

Analysis: [character mesh toggles](../analysis/2026-10-28-character-mesh-toggles.md). Issue: [#88](https://github.com/danirukun/opensekai/issues/88) (BP-08, slice 1). Queue bundle B26.

Status: contract. Not implemented.

Length unit: each length limit in this contract counts UTF-16 code units, as `expression_name_ok` and the asset name check do (`encode_utf16().count()` in Rust, `.length` in TypeScript). "Trim" removes the Unicode white space at the two ends, the same on both sides (`str::trim` and `String.prototype.trim`; a shared vector pins it).

## R — Requirements

1. **Mesh names.** The mesh list of a VRM is the list of the glTF nodes that have a `mesh`, in node order. Each entry is `{node, name}`. `node` is the glTF node index. `name` comes from the node name with these steps, in this order:
   1. Trim the node name. An empty result becomes `Mesh <node>`.
   2. Cut the result to 128 units. Do not cut a surrogate pair in two.
   3. When an earlier entry has the same name, add ` (2)`, ` (3)`, and so on, with the first number that gives a unique name. Cut the base before the suffix so that the base and the suffix together are at most 128 units.
   The list keeps the first 256 entries in node order. A mesh node after the 256th entry cannot be hidden; the importer logs the count that it drops.
2. **One rule in two languages.** Rust (`vrm_meshes` in `apps/desktop/src-tauri/src/assets/vrm.rs`) and TypeScript (`meshEntries(json)` in `packages/contracts/src/meshes.ts`) implement R1. A shared vector file `fixtures/protocol/mesh-names.json` (glTF `nodes` arrays and the expected entries) pins the two: an empty name, a white-space name, repeated names, a 128-unit name with a repeat, an emoji name at the cut, and a 257-mesh list. Rust and TypeScript tests each read it.
3. **Asset record.** The asset record of a VRM gets `meshes`, the R1 list. A VRM import writes it. A VRM record without `meshes` gets it from the stored file in both registry load paths: `load_library` (which writes the record again) and `AssetRegistry::load(manifest)` for fixture manifests (in memory only). The backfill of `meshes` has its own flag, so a record whose rig cannot be read still gets `meshes` and is written again, and a record whose file cannot be read keeps no `meshes` and is not written again for this field. A GLB scene record does not get `meshes` in this slice.
4. **Scene field.** The `avatar` entity gets an optional `hiddenMeshes`: a list of unique names, at most 256, each 1 to 128 units. No field and an empty list both mean that all meshes show. `createEntity` with an empty list stores no field, in TypeScript and in Rust. A show saved before this slice keeps its look. The schema version of the show and the scene stays 1.
5. **Patch op.** `setHiddenMeshes {entityId, hiddenMeshes}` replaces the list of one avatar. It fails with `Entity not found` for a missing entity and `Entity is not an avatar` for another kind. An empty list removes the field. The session applies it as one committed revision, as `setVisibility`. The op does not check the names against the asset (R6). OpenSekai has no scene undo (OSE-09), so this slice adds none.
6. **Unknown names.** A name in `hiddenMeshes` that the mesh list of the model does not have has no effect. It stays in the scene, so a change back to the first model shows the first state again. A change of `assetId` does not change `hiddenMeshes`.
7. **Renderer.** At avatar load, `assets.ts` runs `meshEntries` on `gltf.parser.json` and builds a map from each mesh name to the object of its node (`parser.associations`, or `parser.getDependency('node', index)`). A node with more than one primitive loads as a group; the map holds the node object, not its children. The map goes with the avatar binding; avatars are not cloned. On each scene change, the renderer sets `object.visible = !hidden` on each mapped object, where `hidden` means the name is in `hiddenMeshes`. glTF has no hidden node state, so each mapped object starts visible. Children of a hidden node are hidden with it (Warudo hides a GameObject the same way). The entity `visible` flag still hides the whole avatar. A mesh toggle does not reload the model, change a material, or change the pose, the expressions, or the tracking. The one `createRenderer` serves the OBS page, the Scene preview, the Editor viewport, and the screenshot path, so one change covers each client.
8. **Toggle node.** `character.toggleMeshes`, label `Toggle Character Meshes`, category Character. Settings `{entityId, meshes}`. Ports: input `flow`, output `exit`. The evaluator emits the delta effect `{kind: 'toggleMeshes', entityId, names}`.
9. **Set node.** `character.setMeshesVisible`, label `Set Character Meshes Visible`, category Character. Settings `{entityId, meshes}`. Ports: inputs `flow` and `visible` (boolean; `inputDefaults: {visible: true}`), output `exit`. The evaluator emits `{kind: 'setMeshesVisible', entityId, names, visible}`.
10. **Effects.** `applyEffects` in `scene-ops.ts` resolves the two delta effects in order against the running scene of the run (as it resolves `toggleVisibility` now): `toggleMeshes` removes each listed name that is in `hiddenMeshes` and adds each other one; `setMeshesVisible` removes each listed name for `true` and adds each one for `false`. Each resolved effect applies as a `setHiddenMeshes` operation. So two mesh nodes on one avatar in one run give the final list, and the run commits one revision. A missing entity fails with `Entity not found` and a non-avatar with `Entity is not an avatar`, and the run makes no state change. An effect that gives the current list changes nothing. `applyEffects` gets a branch for each effect kind; the present code sends each non-camera effect to `setVisibility`, so it is restructured, not only extended. `SceneEffect` in `blueprint.ts` gets the two kinds.
11. **Node field.** `meshes` is a new field kind: a list of 1 to 16 unique names, each 1 to 128 units. The editor offers the `meshes` of the asset record of the selected avatar, in record order, with a `+` control to add an entry and a remove control on each entry. A saved name that the record does not have shows as missing, as a missing expression does. `DefaultRefs` gets `mesh` (the first mesh of the record of the default avatar), and the node `defaults` use it, as the expression nodes use `expression`. The `BlueprintPanel.svelte` refs builder sets it. A node added when no avatar has a mesh list has no defaults, as an expression node without an expression.
12. **Inspector.** An avatar whose asset record has a non-empty `meshes` gets a `Meshes` section, after the expressions section. It has one checkbox for each mesh, labeled with the mesh name, checked when the mesh shows. A click sends one `setHiddenMeshes` patch. The section is collapsible, and the section index lists it (`editor/inspector-sections.ts` `sectionsFor`). An avatar with no asset, a record without `meshes`, or an empty list has no section. Controls come from `@oshi-connect/ui`. No helper text.
13. **MCP.** One read tool, `mesh_list {avatarId}`, maps to the new session method `meshList`. It returns `{meshes: {name, hidden}[], unknown: string[]}`: the meshes of the record of that avatar in record order, and the names in `hiddenMeshes` that the record does not have. It fails with `Entity not found`, `Entity is not an avatar`, or `Asset has no mesh list` (no asset, or no `meshes` in the record). `scene_patch` accepts `setHiddenMeshes`; its description names the op in one sentence. `asset_list` does not change. The node catalog (`opensekai://blueprint-nodes`) shows the two nodes and the `meshes` field from the node definitions.
14. **Known gaps**, not in this slice: scene undo (OSE-09); a prop on a human bone or a transform path (Warudo Transform Attachment, CHR-07 and ENV-03, after #242); prop meshes; Default BlendShapes and Default Material Properties; Throw Prop At Character and other prop interactions with collision and ragdoll (needs physics, CHR-09 and BP-10); a list data input for meshes; mesh toggles on a GLB character; mesh nodes after the 256th.

## E — Entities

- `AssetMeshSchema`: `{node: u32, name: MeshName}`. `AssetRecordSchema.meshes?: AssetMesh[]` (at most 256, names unique). Rust: `AssetMesh` and `AssetRecord.meshes: Option<Vec<AssetMesh>>` with `skip_serializing_if = "Option::is_none"`; `AssetRecord::validate` checks the count, each name, and uniqueness.
- `MeshNameSchema`: a string of 1 to 128 units. `AvatarEntity.hiddenMeshes?: MeshName[]` (unique, at most 256). Rust: `hidden_meshes: Option<Vec<String>>`, `rename = "hiddenMeshes"`; `SceneEntity::validate` checks it.
- `PatchOp` `setHiddenMeshes`: `{op: 'setHiddenMeshes', entityId: Id, hiddenMeshes: MeshName[]}` (unique, at most 256). Rust `PatchOp::SetHiddenMeshes` with its own validation arm (not the `_` fallback).
- `MeshList`: `{meshes: {name: MeshName, hidden: boolean}[], unknown: MeshName[]}`. Method `meshList` with params `{avatarId: Id}` (read capability). Rust `MeshListParams` and `MeshList`.
- Blueprint settings `{entityId: Id, meshes: MeshName[]}` (1 to 16, unique). `BlueprintField` gains `{key, label, kind: 'meshes'}`. `DefaultRefs` gains `mesh?: string`.
- Scene effects `{kind: 'toggleMeshes', entityId: Id, names: MeshName[]}` and `{kind: 'setMeshesVisible', entityId: Id, names: MeshName[], visible: boolean}`.
- `packages/contracts/src/meshes.ts`: `meshEntries(json)` (R1), `toggleMeshes(hidden, names)`, and `setMeshesVisible(hidden, names, visible)`. The two edit helpers keep the order of the current list and add new names at the end; a repeated input name has one effect.

## S — Safeguards

- Do not change the show schema version or the meaning of `visible`.
- Do not drop or rewrite a `hiddenMeshes` name when the model changes or the name is unknown.
- Do not reload or re-import a model to hide a mesh. Do not change a material to hide a mesh.
- Do not let Rust and TypeScript make different mesh names: both pass `mesh-names.json`.
- Do not send mesh or image data through Tauri IPC on the output path.
- Do not add a prop attachment, a physics body, a collider, or scene undo in this slice.
- Do not claim BP-08 on macOS or in OBS from the cloud run. The hidden mesh on the OBS output with alpha, the Inspector flow in the macOS app, and a hotkey toggle during tracking need an owner check on macOS (`accept:local`).
